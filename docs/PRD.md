# 상품 작업대 — 공개 제품 초안 PRD v0.1

상태: 목표 정의 초안. 실제 구현 범위는 [구현 현황](implementation-status.md)을 참고합니다. 특정 매장의 운영 자료나 기존 비공개 코드 조사 내용은 포함하지 않습니다.

## 문제와 목표

매장에 신상품이 들어와도 사진 촬영, 정보 입력, 상세페이지 제작 때문에 온라인 등록이 밀릴 수 있습니다. 상품 작업대는 판매자가 실사와 확인된 사실을 모아 일관된 품질의 등록 초안을 만드는 도구입니다. 첫 대상 채널은 스마트스토어이며, 후속 채널은 어댑터로 연결합니다.

일관성은 사실의 정합성·사진 규격·브랜드 말투·정보 완성도를 의미합니다. 상품마다 다른 형태·색상·구성·옵션은 보존합니다. 상품 등록 증가가 검색 유입이나 주문 증가를 보장한다고 가정하지 않습니다.

## 사용자 경험

분석 차트보다 밀린 상품의 다음 행동을 중심에 둡니다. 상품별 촬영 필요, 정보·권리 확인, 초안 준비, 검수·승인, 채널별 등록·수정 상태를 표시합니다. 공통 상품 편집과 채널별 미리보기를 연결합니다.

1. 상품을 대기 목록에 추가하고 촬영 안내를 확인합니다.
2. 원본 사진과 라벨·공급처 자료·직접 입력 정보를 모읍니다.
3. 후보값을 사람이 확인하고, 필요한 정보와 권리 문제는 보류합니다.
4. 확인된 사실로 채널 문구와 실사 상세 초안을 만듭니다.
5. 사진·문구·옵션을 검수하고 특정 버전을 승인합니다.
6. 등록 준비 자료를 내보냅니다. 공식 연동은 별도의 후속 단계입니다.

## 블록 설계 방향

각 기능은 명시적인 입력·출력을 가진 블록입니다. 필요한 기능을 조합하고 실제 다른 사용처가 확인되면 패키지로 추출합니다. 첫 제품은 작은 모듈형 단일 애플리케이션이며, 드래그앤드롭 편집기·범용 플러그인 마켓·마이크로서비스는 목표에 포함하지 않습니다.

| 블록 | 입력 → 출력 |
|---|---|
| 촬영 안내 | 상품군·옵션·현재 컷 → 필요한 사진 체크리스트 |
| 자산 관리 | 사진·출처 → 원본·파생본·해시·역할 |
| 후보 추출 | 라벨·자료·수동 입력 → 출처 연결 후보 사실 |
| 사실 검수 | 후보값 → 판매자 확인 사실·변경 이력 |
| 권리 확인 | 상품·자산·대상 채널·증빙 → 사용 범위·보류 사유 |
| 채널 문구 | 확인 사실·말투·채널 규칙 → 상품명·속성·설명 후보 |
| 상세 구성 | 실사·사실·템플릿 → 편집 블록·미리보기·출력 |
| 승인 | 초안·사실·자산·권리·규칙 버전 → 승인 스냅샷 |
| 채널 어댑터 | 승인 버전·대상 채널 → 내보내기 또는 공식 등록 결과 |

공통 계약에는 입력/출력 스키마, 상품·자산 버전 lineage, 구조화 오류와 재시도 조건, 실행 권한과 승인 종류, 비용·저장·외부 전송·등록 부작용이 포함됩니다. 블록이 실패해도 기존 입력과 초안을 보존하며, 지원하지 않는 기능은 명시적으로 반환합니다.

기본 흐름은 촬영 안내 → 자산 관리 → 후보 추출 → 사실 검수 → 권리 확인 → 채널 문구 + 상세 구성 → 승인 → 내보내기입니다. 후보 추출은 수동 입력으로 대체할 수 있습니다. 이미 촬영한 자료는 안내 단계를 생략할 수 있으나 검증·승인은 생략하지 않습니다.

## 공통 데이터 방향

| 개체 | 역할 |
|---|---|
| Product | 공통 상품 ID·상품군·버전·상태 |
| Fact | 필드·값·단위·출처·확인 상태 |
| SKU | 옵션 조합·가격·입력 재고·사진 연결 (후속) |
| Asset | 원본·해시·변환 이력·출처·권리 참조 |
| RightsRecord | 사용 범위·채널·기간·증빙·검토 상태 (현재는 단순 확인 모델) |
| ChannelDraft | 채널·원본 버전·규칙 버전·편집 결과 |
| Approval | 검수자·시각·승인한 내용의 해시 |
| ChannelListing | 원격 상품 ID·등록 상태 (후속) |

채널별 출력은 공통 사실을 조용히 덮어쓰지 않습니다. 사실·사진·가격·문구·권리의 변경은 영향받는 초안·승인을 재검토 대상으로 만듭니다. 인증 정보는 상품 데이터와 분리합니다.

## 핵심 수용 기준

- 미확인 소재·원산지·인증·효능을 사진만 보고 확정하지 않습니다.
- 원본 사진을 보존하고 생성·편집 결과에서 상품 외형을 왜곡하지 않습니다.
- 필요한 사진 사용 권한·채널 판매 범위가 미확인 상태면 승인·내보내기를 막습니다.
- 승인 이후 내용이 바뀌면 승인을 무효화하고 내보내기 시 해시를 재확인합니다.
- 원본 버전이 다른 블록 결과의 결합을 거부합니다.
- 내부 증빙·검토 메모·인증 정보는 공개 패키지에서 제외합니다.
- 내보내기, 원격 접수, 실제 등록·판매 상태를 구분합니다.
- 원격 응답이 불명확할 때 무조건 재제출하지 않습니다.
- 수동 입력·편집과 오류 복구 경로를 유지합니다.

권리 확인은 법적 적합성을 자동 판정하는 기능이 아닙니다. 사진·문구 사용, 상품 관련 권리, 공급 계약상 채널 제한을 구분해 판매자가 검토하도록 돕습니다.

## 범위와 단계

1. 로컬 초안: 작업 목록·원본 사진·확인 사실·권리 보류·편집·승인·수동 준비 자료 출력.
2. 실사용 검증: 소수의 실제 미등록 상품으로 시간·수정·보류 사유를 측정하고 등록에 필요한 자료 구조를 보완.
3. 공식 스마트스토어 연동: 공식 기준·이용 자격·계정 권한 확인 후 등록·수정·상태와 중복 제출 방지.
4. 추가 채널: 실제 수요가 있을 때 쿠팡 등 채널별 매핑·검증·등록 어댑터를 추가.

실시간 재고·주문·정산·광고 운영·SNS 자동 게시·영상 제작·검색 순위 보장은 초기 범위에서 제외합니다.

## 검증과 열린 결정

첫 현장 검증은 실제 미등록 상품 5개를 제안합니다. 촬영부터 준비 완료까지 활성 작업 시간과 대기 시간, 사실/이미지/문구 수정 부담, 준비 완료와 실제 등록 수를 구분해 측정합니다. 목표 수치와 유입·주문 성과는 아직 검증하지 않았습니다.

확인할 항목은 권리 이슈의 유형, 첫 상품군과 옵션 복잡도, 필수 상품정보·배송 규칙, 채널 연동 자격, 자료 보존·삭제·백업 정책, 생성 비용과 승인 주체입니다. 로컬 초안의 구현 여부는 별도 현황 문서에서 관리합니다.
