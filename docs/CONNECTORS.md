# v0.3 실제 연결 구성

현재 AI 연결은 `agent/src/agents/product.ts`의 Flue 에이전트와 OpenRouter입니다. `src/blocks/providers.ts`는 이전 모의 후보 추출 계약이며 실연결 경로가 아닙니다.

`POST /api/propose`: 공개 상품 정보·사진·수정 요청 → Flue `inspect_product` → `submit_proposal` → 검증된 제안. `GET /api/health`: 키 설정 여부와 모델명만 반환합니다. 키 값은 응답하지 않습니다.

키는 루트 `.env`의 `OPENROUTER_API_KEY`, 모델은 `OPENROUTER_MODEL`. 실제 키 호출은 미검증입니다. 로컬 서버 전용으로 인증·인터넷 배포는 제공하지 않습니다. 공식 스마트스토어 API는 여전히 미연결입니다.

# 외부 연동 준비와 경계

현재 사용 흐름은 키 없이 로컬에서 완결됩니다. 공식 API를 호출하거나 인증 정보를 읽지 않습니다.

## AI/OCR

`src/blocks/providers.ts`는 상품 ID·원본 버전·사진 ID를 입력받아 출처가 붙은 텍스트 후보를 반환하는 선택형 인터페이스입니다. 현재 `mock`만 계약 테스트에 사용하며 `live`와 미설정은 `UNSUPPORTED`입니다. 원본 버전이 다른 결과는 거부하고 후보는 사람 확인 전까지 확정하지 않습니다. UI에는 실공급자 설정이 없습니다.

실연결 전에는 전송할 사진/자료, 제공자 데이터 정책, 사용자 승인, 호출 비용·상한, 취소/재시도, 보관 기간, 비밀값을 브라우저에 노출하지 않는 서버 경계를 결정해야 합니다. 수동 입력 경로를 유지합니다.

## 스마트스토어

`src/blocks/smartstore-mock.ts`는 승인된 공개 준비 자료와 카테고리·배송·고시 검토 참조를 결합한 **내부 등록 의도**입니다. 공식 API payload가 아니며 참조값의 공식 유효성을 판정하지 않습니다. 원격 `create/update/status`는 모두 미지원입니다.

공식 상품 등록은 커머스API의 `POST /v2/products` 문서를 기준으로 필수 필드와 오류 응답을 별도로 매핑해야 합니다. 인증은 공식 OAuth 문서와 이용 자격을 확인해야 하며 이 앱에 자격 증명 발급·토큰 저장·실계정 연결을 구현하지 않았습니다. 참고: [네이버 상품 등록 문서](https://apicenter.commerce.naver.com/docs/commerce-api/current/create-product-product), [네이버 인증 문서](https://apicenter.commerce.naver.com/docs/commerce-api/current/exchange-sellers-auth). 문서는 2026-11-02에 확인했으며 실제 연결 시 최신 버전을 다시 확인합니다.

후속 완료 조건:

1. 판매자/애플리케이션 이용 자격과 최소 권한을 확인하고 서버에서 비밀값을 관리한다.
2. 공통 Product와 채널 필수값의 검증·매핑·미리보기를 구현한다. 고시·인증·원산지 등을 추측하지 않는다.
3. 승인한 정확한 내용/버전만 쓰도록 하고 변경 시 승인을 해제한다.
4. 중복 요청, 오류별 재시도, 등록 후 상태 대사·수정 충돌을 테스트한다.
5. 실제 등록은 별도 허용된 계정과 범위에서 검증한다. 현재 수동 출력 성공을 공식 등록 성공으로 취급하지 않는다.

쿠팡은 후속 채널입니다. 공통 상품 스키마를 유지하며 지원 가능한 기능을 명시하는 어댑터를 추가할 계획이고, 현재 지원을 주장하지 않습니다.
